\subsection{A time-varying capital exponent for OG-Core}
\label{app:patch}

Stock OG-Core indexes the capital exponent by industry only, as \texttt{p.gamma[m]}, at about \genPatchSites{} sites in \texttt{ogcore/firm.py}. Automation can therefore step to a new level in the first period but cannot phase in. The scenarios used here phase in over \genShockYear--\genHeadYear{}, and \citet{mollimas2026} raise the exponent over two decades. Neither can be run without a time dimension.

The patch (\texttt{patches/ogcore-0.17.0-firm-gamma-tv.diff}, against OG-Core \genOgcoreVersion{}) adds one in a backward-compatible way. A helper indexes a production parameter that may carry either shape, following the convention $Z$ already uses: the last row in the steady state, the first $T$ rows along the transition.
\begin{verbatim}
def _tv(x, p, method, m=None):
    x = np.asarray(x)
    if x.ndim <= 1:                 # (M,) -- time-invariant, legacy
        return x[m] if m is not None else x
    if method == "SS":              # (T, M) -- time-varying
        return x[-1, m] if m is not None else x[-1]
    return x[: p.T, m] if m is not None else x[: p.T]
\end{verbatim}
Every \texttt{p.gamma[m]}, \texttt{p.gamma\_g[m]} and bare \texttt{p.gamma} is replaced by \texttt{\_tv(p.gamma, p, method, m)}. A one-dimensional parameter is returned exactly as before, so existing calibrations are bit-identical. \texttt{get\_MPx} also needs the share in column shape along the transition, or a $(T,)$ share forms a $(T,T)$ outer product.

As a regression check, the single-sector scenario with a one-dimensional exponent reproduces the unpatched run exactly. As a capability check, an exponent ramping from \genGammaBase{} to \genKorinekGammaTerminal{} solves and produces a labour-share path rather than a step. The runner refuses to start against an unpatched \texttt{ogcore.firm}. The patch is not upstream.

\subsection{Reproduction}
\label{app:reproduction}

Runs used OG-Core \genOgcoreVersion{} with the patch above, OG-UK at commit \genOgukSha{} and PolicyEngine UK \genPolicyengineUkVersion{}. OG-UK reads PolicyEngine's UK data from Hugging Face, so a re-run needs a token. The design and the solve plan are in \texttt{docs/surprise\_2028.md}; the calibration in \texttt{docs/uk\_calibration.md}. The paper reads only committed files. From the repository root:

\begin{verbatim}
python paper/make_values.py --check     # values_generated.tex is current
cd paper && tectonic main.tex           # or: pdflatex main && pdflatex main
\end{verbatim}

Every number is a macro in \texttt{paper/values\_generated.tex}, generated from the per-solve records in \texttt{analysis/surprise/output/<closure>/}. \texttt{make\_values.py} stops with an error if a record is missing (other than the solves still queued, which print as pending), if a record fails its checks, or if a sentence that the paper states in words (for example, that debt/GDP is higher by \genDebtRuleYear{} in every arm) no longer holds.
